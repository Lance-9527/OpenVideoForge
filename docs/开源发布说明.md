## 二、已处置的问题

### 2.1 本机绝对路径（最严重的一类）

原先默认值写死成开发机的盘符路径（产物目录、数据目录、截图目录、Blender 目录、
Python 解释器、VideoForge 源码目录……）。后果：别人装上就跑不起来，且会暴露
本机目录结构与 Windows 用户名。

处置：

- 新增 `server/paths.mjs` 统一管理默认路径：
  `defaultOutDir()` / `defaultDataDir()` / `defaultShotsDir()` /
  `defaultToolsDir()` / `defaultProfileDir()` / `findBlender()`。
  口径统一为 **环境变量优先 → 否则用系统标准的用户目录**。
- `server/`、`bin/`、`tools/`、`tests/`、`agent-side/` 共 60+ 处硬编码路径改为
  调用上述 helper；`.ps1` 脚本改为从 `PATH` / 环境变量解析 Python 与 Blender。
- 文档里的路径改为占位符（`<输出目录>` / `<数据目录>` / `<截图目录>` …）。

### 2.2 MCP 配置指向不存在的 npm 包

`.mcp.json` 与 `plugin/plugin.json` 原先写着 `npx -y openvideoforge mcp`，
但**这个包从未发布到 npm**（实测 404）——照着配的人会直接失败。

处置：改成源码方式 `node bin/cli.mjs mcp`，并在 README 明确写出
「本项目暂未发布到 npm，请用源码方式或先 `npm link`」。

### 2.3 第三方许可声明与实际文件不符

- 原文件写的是 `product/js/vendor/...`——该目录早已不存在（现为 `js/vendor/`）。
- `assets/three.module.js`（three.js r160 核心构建，1.2MB）**没有列进声明**。
- 项目名还停留在 `whitebox-workbench`。

处置：重写 `THIRD-PARTY-NOTICES.md`，补齐 three.js 核心与 `RGBELoader.js`，
补上 OpenStreetMap（ODbL）的署名义务与 Blender 的「仅外部调用、未链接」说明。

### 2.4 会改本机文件的个人脚本

`tools/patch-delivery*.py` / `tools/patch-geocode.py` 改的是本机 VideoForge
交付目录里的说明文档，不属于本项目代码。已加进 `.gitignore`（本地保留，不入库）。

### 2.5 其它

- `package.json`：`repository.url` 原是占位符 `your-org/whitebox-workbench`，
  改为本仓库地址；补 `homepage` / `bugs` / `author`；加 `"private": true`
  防止误发 npm（要发布时去掉即可）。
- README：原 58KB 是开发流水账，含 21 处本机路径。改为：
  新写一份精简的开源 README（定位 / 快速开始 / MCP 接入 / 能力 / 目录 /
  环境变量 / 已知限制 / 许可），原流水账移到 [`开发记录.md`](./开发记录.md)。
- `AGENTS.md` 的「不动 C 盘」规矩改写成「产物落到可配置目录」，并把其中的
  本机路径换成占位符。
- `.gitignore` 补 `__pycache__/`、`*.py[cod]`、`.env`、`.pytest_cache/`。

## 三、留给后来者的硬规矩

1. **不要把本机路径写回代码**。要默认路径就用 `server/paths.mjs` 里的 helper，
   要临时目录就用 `os.tmpdir()`。
2. **提交前跑一遍密钥扫描**（本页表格第 1、2 项的两条正则）。
3. **加了第三方二进制/字体/模型**，同步更新 `THIRD-PARTY-NOTICES.md`。
4. **改了默认目录口径**，同步更新 README 的「环境变量」表。
5. **引入 OSM 数据或对外发布作品**，必须带 `© OpenStreetMap contributors`。
